# 赤ちゃん動画制作

目的は、根拠を確認した育児情報を保護者に届く短い動画にすること。ゴールは1080×1920・10秒以内のMP4と、貼り付け用の投稿キャプション全文を一緒に提示すること。

## 作業場所

このSKILL.mdのあるディレクトリをスキルルートとする。相対リンクはチャットの現在地ではなく、このファイルの場所を基準に解決する。

最初に[実行ガイド](runtime/README.md)と[本番設定例](runtime/examples/job.live-template.json)を読む。再開では既存job、runの状態・判断履歴・費用台帳を先に確認する。単なるスキル起動を過去runの有料続行や改訂の承認として扱わない。

新規作業の保存先は利用者指定を優先し、指定がなければ現在のプロジェクトの`baby-video-production/`とする。[scripts/init-workspace.py](scripts/init-workspace.py)を使って同梱runtimeをコピーする。既存の作業場所には再初期化せず、その実装と履歴を利用する。インストール先のruntimeに秘密値や制作物を保存しない。既存プロジェクトのAGENTS.mdと保存先ルールを守る。

```bash
python3 <スキルルート>/scripts/init-workspace.py --workspace <作業場所>
```

CLIの作業ディレクトリはコピー先とする。依存を準備して`python3 -m baby_video doctor`で読み取り確認する。キーは利用者自身が、その作業場所の`.env.local`へ入力する。既存キーを別プロジェクトから探さず、値をチャット・ソース・job・ログへ出さない。

この実装はCodexの内蔵image_genを使う。利用できない場合はその不足を伝え、別の有料画像APIへ勝手に切り替えない。日本語の推敲には導入済みのyomiyasuがあれば使ってよいが、必須依存ではない。

## 記事と台本

URLが未指定なら自分で記事を探す。指定URL・テーマがあれば優先し、なければ一般の保護者に身近な育児テーマを選ぶ。再開・修正では対象runの記事・承認を維持する。

自治体、公的機関、専門学会、医療機関などの一次情報を検索し、記事全文を読む。発行元、更新日、対象年齢、条件を確認する。検索抜粋だけを根拠にしない。10秒で一つのメッセージを伝えられる内容を選び、診断、治療指示、根拠のない安全保証を避ける。根拠が足りなければ別の記事を探す。

`source.md`にはタイトル、発行元、URL、公開・更新日、不明な日付、確認日、選定理由、採用する事実と該当箇所を残す。記事全文の転載は不要。jobの`article_url`・`article_file`を対応させ、実際に確認してから`source_facts_reviewed`をtrueにする。

セリフ10案を作り、各案の`text`・`estimated_seconds`・`evidence`を記録する。内容から推奨案を選び、`selection_mode: "agent"`、0〜9の`selected_candidate`、短い`selection_reason`を設定する。自然な日本語で赤ちゃんの視点を表現し、映像プロンプトをセリフに混ぜない。

Fishの生成速度1.1で発話実測8.5〜10秒、目標9秒前後、音声全体が映像尺内という条件に合わせる。同じ声・モデル・速度での実測があれば見積もりに使う。比較資料がない場合は推定と明記し、単一の過去音声と文字数の比例だけで尺を断定しない。

採用台本と出典を提示し、初回台本への承認を待つ。すでに提示した台本への「全て進めて」などの続行指示は承認として記録し、聞き直さない。記事選定だけで課金を開始しない。承認は今回のrunだけに記録し、別runの承認を流用しない。

## 制作と検査

```text
記事と根拠 → 台本承認 → Fish音声（生成速度1.1）
                           ↓
男の子の赤ちゃん画像 → H3（9秒指定）→ 1080×1920変換
                           ↓
                 Klingリップシンク ← 実測した音声
                           ↓
                 実測字幕・Remotion・BGM
                           ↓
                 完成動画 ＋ 投稿キャプション
```

台本承認後は`review_policy: "script_only"`で進め、各工程の終了を人間の確認待ちにしない。CLIの`waiting`・`review_required`はエージェントへの引き継ぎ。実ファイルを検査し、[実行ガイド](runtime/README.md)の`decide`で判断を記録して同じrunを`resume`する。

| 工程 | 必須checks |
| --- | --- |
| source | text_read |
| dialogue | text_read。初回承認はactor: human、承認範囲内の尺改訂はcodex_agent |
| audio | technical_checked |
| image | image_viewed |
| video | technical_checked, image_viewed |
| upscale | technical_checked |
| lipsync | technical_checked, image_viewed |
| edit | text_read, technical_checked, image_viewed |
| description | text_read |

音声は`fish_speed: 1.1`を生成時の`prosody.speed`へ渡す。最初の発話開始から最後の発話終了までを測り、自然な文間は含め、冒頭・末尾無音は除く。ファイル全体の尺と区別して記録する。復号、ASRと台本の一致、欠落、無音、クリッピングも確認する。完成音声の速度変更、切断、末尾無音の追加で尺を合わせない。

画像は架空の男の子の赤ちゃんを標準とし、プロンプトに「男の子の赤ちゃん」または`baby boy`を明記する。動物服、顔・口が見える構図、手や玩具が口を隠さない配置を使う。利用者の参照画像がある場合は画素と使用許可を確認する。参照なしの架空顔は許可を確認し、`image_reference_mode: "original_fictional"`・`new_fictional_face_authorized: true`を設定する。既存画像をこの標準だけで再生成しない。

内蔵image_genの結果を確認して`import-image --tool-generated`で取り込む。CLIは画像ツールを直接呼べない。代用品をツール生成として申告しない。

H3は9秒・480Pで生成し、実尺を確認して1080×1920へ変換する。Klingと完成動画も10秒以内。超過素材を次の課金工程へ送らない。[動画プロンプト例](runtime/examples/video-prompt.txt)の自然な笑顔と口が動く指示を使う。表情の自然な変化は許容し、笑顔だけを理由に有料再生成しない。

BGMは利用範囲に合う許諾を確認したローカル音源を`bgm_file`へ設定する。実装には音源を同梱していない。声を妨げない音量とフェードを使う。

字幕はローカルwhisper.cpp、DTW、実測音声活動を使う。照合が不確かな場合はASR・波形・フレームを確認し、文字数の均等配分を音声同期と呼ばない。一度に短い1フレーズを1行で表示し、目安3〜9字の意味単位で区切る。台本全文の文字数制限ではない。白い丸ゴシック、黒縁、左右中央、高さ約66%の位置を標準とする。

実音声の聴取や全編視聴が可能なら行う。不可能なら`unverified`へ残し、技術検査・実画素で確認できる範囲を調べて進める。聴取・全編視聴済みと偽らない。判断JSONは短い観察の`summary`、実施した`checks`、run内の`evidence_files`、残る`unverified`を使い、私的な思考過程は保存しない。本番で`mock_test`を使わない。

最後のdescription工程では[キャプションガイド](references/instagram-caption.md)を読む。利用者の投稿先・語調を優先し、未指定なら同梱のオリジナル例を型として使う。本文を`inputs/description.md`へ保存し、追加の確認を挟まず納品する。

## 改訂と費用

同じrunで`revise --job <job> --run <run> --reason <理由>`を使い、必要な下流だけを無効化する。旧素材、判断、支出、受付不明の予約額を保持する。新しい作業場所やrunを作って既存予算・予約をリセットしない。

音声が短すぎる、長すぎる、映像尺に収まらない場合は、同じ記事・主題・根拠・語調と承認予算の範囲で言い回しを自動改訂する。`timing_revision_authorized: true`、理由は`尺調整:`で始め、根本工程はdialogue。変更前後の台本、理由、推定尺、実測結果を記録し、再承認を求めず`actor: codex_agent`で判断する。無料であることを確認できる音声再生成に限り自動で行い、有料下流の再生成は追加の明示依頼が必要。

有料APIの実行は今回の利用者の許可と利用環境の指示に従う。作者の過去承認は存在しないものとして扱う。許可を確認した範囲だけで`budget_usd`・`cost_caps_usd`を設定し、`standing_spending_authorized`をtrueにする。料金・音声の権利・データ取扱い・falの`public_expiring`方針を実確認する。インストールや台本の準備依頼を課金許可へ拡張しない。

同じ制作への許可がある間は工程ごとに確認を求めない。予算超過、新しい主張、記事・主題変更、新契約、キー作成・権限変更、SNS投稿は別の許可に従う。有料素材は予算内でも追加依頼なしに再生成しない。

受付不明の要求を再送しない。既存request_idを照会し、予約額を残す。確認済みの終端失敗だけを`confirm-failed`・`retry-failed`で扱い、実費は請求確認後に`settle-cost`へ記録する。仮見積、確定実費、予約額を区別する。

## 既存動画の編集

字幕・BGMだけの依頼では元の発話とタイムラインを保ち、記事探索やFish・H3・Klingへ戻らない。新規音声の速度1.1や8.5秒下限を既存動画へ適用しない。

実測時刻付きの字幕JSONを用意し、`scripts/edit-existing-video.py --video <動画> --captions <字幕JSON> --output <別名MP4>`を使う。BGMは`--bgm`で指定する。既存の元動画を上書きしない。書き出し後に字幕内容・時刻・画面内への収まりと音声を検査する。

## 納品

利用者指定の納品先を優先し、未指定なら作業場所の`output/`へ日本語で内容が分かるファイル名でMP4をコピーする。異なる動画が同名なら日付や版番号を付け、上書きしない。コピー後はSHA256一致を確認し、素材・job・run・判断履歴は作業場所へ残す。

完成動画のプレビューまたはリンクと、改行を保ったキャプション全文を同じ最終回答に載せる。キャプションのファイルリンクだけで済ませない。run、出典、確認範囲、未確認事項、確定実費と予約額は投稿本文の外に短く示す。模擬出力を本番生成として報告しない。SNS投稿は別の明示依頼がある場合だけ行う。
